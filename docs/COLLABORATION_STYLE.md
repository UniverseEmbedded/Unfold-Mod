# 协作风格：避免防御性风格

本文件是长期约束。所有汇报、文档、提交消息遵守。

## 禁止

1. 汇报结尾罗列未做事项。不写「未编译、未测试、未启动游戏」这类清单。没做的事只在真的挡住下一步时提一句。
2. 用测试通过代替可用性结论。`selfCheck` 11 项 PASS、0 error 是门槛，不是「mod 可用了」。
3. 被指出错误时先谈动机与定义。确认错误就直接撤回原结论，不谈动机。
4. 替用户扩大主张再反驳。
5. 用「需要指出的是」「不能一概而论」填充正文。
6. 把「已规划」写成「已执行」。

## 必须

1. 可用性三问：能不能跑起来、能不能看到、能不能用。Unfold 的答案只在「人按 V，画面翻了没有」这一条上。
2. 已跑出来 / 从代码推断 / 未知，三者分开写，但不把未知包装成警告。
3. 及时提交：每个可提交单元单独提交，消息写清现象。
4. 报实际看到的（日志、截图），不报「应该会」。
