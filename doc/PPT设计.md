### 1. 项目概述 (Project Overview)

#### 1.1 项目愿景 (Vision)

`Unfold Mod` 旨在将经典益智游戏《纪念碑谷》(Monument Valley) 和《FEZ》的核心玩法——**基于视错觉的空间操纵**——带入《我的世界》(Minecraft) 的三维世界。我们希望打破玩家对三维空间的固有认知，通过“展开”世界，将深度信息压缩，创造出全新的探索路径和解谜可能性。

#### 1.2 核心创意 (Core Idea)

通过一键切换，玩家可以将标准的透视投影（Perspective Projection）世界，转变为一个没有深度信息的正交投影（Orthographic Projection）世界。在这个“展开”的视图下，原本因距离而无法到达的两个平台，只要在视觉上是相连的，玩家就可以通过智能的自动传送系统在它们之间穿梭。

#### 1.3 灵感来源 (Inspiration)

*   **《纪念碑谷》**: 提供了核心的**斜角模式 (Isometric Mode)** 灵感，包括优雅的建筑风格和基于视觉错位的路径连接。
*   **《FEZ》**: 提供了**水平模式 (Horizontal Mode)** 的概念，即在2D平面上旋转3D世界来发现新的通路。
*   **OrthoCamera Mod**: 在正交投影矩阵的实现上提供了宝贵的技术参考。

### 2. 核心概念与玩法设计

#### 2.1 空间维度压缩

这是模组的理论基础。在正交视图下，Z轴（深度）信息被视觉移除。一个在 `(X=0, Y=0, Z=0)` 的方块和一个在 `(X=0, Y=0, Z=100)` 的方块，在屏幕上看起来是重合的。我们的模组正是利用了这一点，让玩家可以在这两个点之间“欺骗”物理规则。

#### 2.2 直觉驱动的传送 (Intuition-Driven Teleportation)

我们摒弃了需要玩家手动瞄准、点击的传送方式。传送完全由玩家的**移动意图**驱动。
*   **当玩家走向一个视觉上的“悬崖”**，系统会自动检测“悬崖”下方或后方是否存在视觉上重叠的平台。
*   **当玩家走向一个视觉上的“高墙”**，系统会自动检测“高墙”顶端是否存在可通行的路径。

#### 2.3 模式分离 (Mode Separation)

为了应对不同视角的玩法需求，我们将游戏分为三种主要模式：

*   **斜角模式 (Isometric)**: 核心玩法，已高度完善。
*   **水平模式 (Horizontal)**: FEZ风格，开发中。
*   **垂直模式 (Vertical)**: 俯视/仰视，开发中。

### 3. 算法深度解析：斜角模式传送系统

这是整个项目的技术核心与最大亮点。我们经历了一个从复杂到优雅的迭代过程，最终实现了一套精确、可控且符合直觉的算法。

#### 3.1 算法的演进

1.  **初代设想：多辅助线暴力探测**
  *   **思路**: 从玩家碰撞箱的多个点（如8个角）发射射线。
  *   **问题**: 逻辑极其复杂，需要处理大量射线组合，性能开销大，且经常出现不符合直觉的“意外”传送。**失败。**

2.  **二代设想：单辅助线 + 几何推断**
  *   **思路**: 使用一条关键的辅助线，但其位置基于对偏航角（Yaw）的数学范围推断。
  *   **问题**: 几何关系极易出错，导致在不同视角下，辅助线的位置与玩家直觉完全不符。**多次修正后依然失败。**

#### 3.2 最终算法：动态单辅助线 + 双向探测 + 阴影安全区

这是我们最终采用的、被证明完全成功的方案。

**A. 动态基准点 (`pivotPoint`)**

我们放弃了所有数学推断，采用了一个基于`switch`语句的**精确查找表**。它能根据当前的`ViewDirection`（东北、西南等），为玩家碰撞箱在当前视图中**“最靠后”（最靠近屏幕）**的那个顶点，计算出绝对正确的世界坐标。这是整个算法的基石。

**B. 统一单辅助线，双向探测**

整套传送逻辑都基于这个动态的`pivotPoint`。
*   **高处探测 (`highProbe`)**: 通过一条从远处**射向**`pivotPoint`的反向射线，模拟从相机视线方向的遮挡判断。它负责寻找可以**向上**传送的平台。
*   **低处探测 (`lowProbe`)**: 通过一条从`pivotPoint`**射向**远处的正向射线，模拟玩家“跌落”的路径。它负责寻找可以**向下**传送的平台。

**C. 阴影安全区 (辅助线2 - `shadowProbe`)**

这是实现高级控制、防止意外传送的关键创新。
*   **目的**: 允许玩家在建筑物的阴影下行走，而不会被意外传送到头顶的平台上。
*   **实现**: 创建一条比主探测线（辅助线1）**更靠内**的“阴影探测线”。
*   **规则**:
  1.  系统**首先**探测阴影探测线。
  2.  如果这条线被**不同于**玩家当前高度的方块遮挡（即前方是墙壁或高台），则设置一个标志位，**禁止**本次tick的**向上**传送。
  3.  如果这条线畅通无阻（或只探测到同高度地面），则**允许**向上传送。
  4.  向下传送**永远不受**此限制。

**D. 沿视线投影传送 (`projectPlayerToTargetY`)**

这是实现完美视错觉效果的最后一步。
*   **问题**: 简单的瞬移会改变玩家在屏幕上的2D位置，导致画面跳跃。
*   **解决方案**: 通过线性代数计算，将玩家的当前3D位置，沿着视线方向（展开线 `unfoldAxis`）进行精确投影，直到其Y坐标与目标平台的高度相匹配。
*   **效果**: 玩家在屏幕上的位置保持不变，只改变了其在世界坐标系中的深度，实现了无缝、平滑的深度传送。

#### 3.3 最终算法图解

```
      <-- 展开线 (unfoldAxis) -- [相机方向]


[远处] <--- highProbe / shadowProbe --- [作用点] ---> lowProbe ---> [远处]
                                      |
                                      |
             +Z                       |
             ^                        |
             |                        |
      +---+--+---+                    |
      |NW |  |NE |       玩家碰撞箱底面(世界坐标)
      +---+--+---+                    |
      |SW |  |SE |                    |
      +---+--+---+---> +X             |
                                      |
                                      |
      * pivotPoint (辅助线1作用点, 偏移0.01格)
      * shadowProbePoint (辅助线2作用点, 偏移0.11格)

      示例：当视角为“西南俯视”(ISO_NEG_X_NEG_Y)时,
            “屏幕后方”的顶点是世界坐标的 (-X, +Z) 角 (即NW角)。
            pivotPoint 和 shadowProbePoint 会基于此角计算。
```

### 4. 工程实现与架构

#### 4.1 渲染管线注入

通过 **Mixin** 技术，我们对Minecraft客户端的核心渲染类进行了无侵入式修改。
*   `GameRendererMixin`: 将原生的**透视投影矩阵**替换为我们自定义的**正交投影矩阵**，并强制锁定相机旋转。
*   `CameraMixin`: 完全禁用鼠标在展开模式下对视角的控制，确保视图的绝对稳定。
*   `WorldRendererMixin`: 通过在`setupTerrain`方法开头注入并取消后续代码执行，完全绕过原生的**视锥体剔除 (Frustum Culling)**，从根源上解决了正交投影下远景区块被错误剔除的问题。

#### 4.2 逻辑与状态管理

*   `UnfoldManager`: 一个全局静态类，负责管理核心状态，如 `unfolding` (是否处于展开模式), `currentDirection`, `currentMode`。
*   `ViewDirection`: 枚举类，定义了所有预设的视角方向（包含中文名称用于调试）。其`getClosest()`方法经过修正，能优先判断垂直视角。
*   `UnfoldMode`: 枚举类，定义了三种游戏模式。其`fromPlayerPitch()`方法能根据玩家实际俯仰角精确判断模式。

#### 4.3 自动化测试框架

为了保证复杂算法的稳定性和正确性，项目内置了一个强大的客户端自动化测试框架。
*   `TestRunner`: 负责管理和执行一系列预设的测试用例。
*   `TestTask`: 定义了测试步骤的接口，如场景搭建 (`BuildPlatformTask`)、模拟玩家移动 (`SimulateMoveTask`) 和结果断言 (`AssertPositionTask`)。
*   **指令驱动**: 可以通过游戏内指令 `/unfold test <test_name|all>` 启动测试，极大地加速了开发和调试循环。

**第10页：工程架构 (Engineering & Architecture)**
